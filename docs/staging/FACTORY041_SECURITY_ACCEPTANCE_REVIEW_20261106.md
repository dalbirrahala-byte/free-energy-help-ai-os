## Findings and disposition

* **F1 — Operational information exposure / privileged database work.** The Preview readiness path bypassed CRM middleware and did not check caller identity before connecting both restricted DB identities. Network-level Preview protection was its only access boundary. Removed the exception; the GET handler now checks the verified user, admin role and AAL2, denying on error before any readiness DB call. Integration coverage exercises the denial boundary and path matcher; real hosted login/MFA evidence remains open.
* **F2 — Login privilege drift concealed by SET ROLE.** The check formerly examined elevated flags of the assumed role only. A misprovisioned worker login with CREATEDB or an extra membership could still report healthy. Check both principals, unexpected memberships (including on the assumed role), raw queue access and membership options inside each transaction. A real local PostgreSQL catalog test adds/removes CREATEDB, an extra login membership, a capability membership, and direct SELECT. Each drift blocks verification, restoring each original grant restores the local health check. This detector does not revoke grants or replace a complete hosted ACL audit.
* **F3 — Owner approval could silently follow a modified consent mapping.** The private SQL draft persisted the binding ID. Its fingerprint protected the approval click, but later in-place edits to the notice, answers, source or recipient could reuse the same ID. Enforce immutable binding rows with an UPDATE rejection. Changes require a new row and owner adoption. The SQL test attempts to invert YES/NO after adoption and confirms a recorded refusal cannot dispatch. No change to installed migrations.
* **Boundary limits.** Google/Meta, Telnyx and supplier responsibilities remain separate: these routes have no supplier-order API. Only verified enquiries can reserve; the recorder cannot approve, and the scheduler/trigger is not consent. Approval is limited to one binding, validated phone, one enquiry and 15 minutes; a phone alone cannot qualify. Claim, consumption, durable preparation, final destination/suppression/STOP check and finalisation remain separate. An interrupted claim, timeout or unmatched callback needs reconciliation, never a blind CREATE retry. Real HTTP transport currently accepts only the historical v1 text. Do not widen that transport as part of this checkpoint. The v2 acceptance path uses a mock. Actual verified provider answer bindings, Google key rotation and retained email readback are still required.
* **Deployment and recovery risks.** The Meta staging test expiry is hard capped at 6 Nov and the restricted receiver has a dated login window; do not automatically renew them. No general production recipient rule is assessed. Independent-session races, the last-check-to-provider-call timing boundary, hosted MFA, real callback ingress, durable reconciliation/monitoring and hosted five-group evidence remain open. The Git path comparison intentionally covers five existing path roots; helper code and the noninstalled authority draft are reviewed at the pinned whole-code commit but are outside that comparison.
